# Learned candidate ranking (LambdaMART)

GraphMem can optionally re-rank its retrieved scope candidates using a learned LightGBM LambdaMART model. The existing manually weighted ranker remains the default and is unchanged unless `--ranker` is supplied.

## 1. Install dependencies

From the repository root, install/update the project:

```bash
pip install -e .
```

LightGBM is included in `pyproject.toml` and `requirements.txt`.

## 2. Train a first model

Start with a small run to validate the complete pipeline:

```bash
python scripts/train_ranker.py \
  --max-instances 30 \
  --repo-dir .cache/swebench-repos \
  --model-out models/graphmem-lambdamart.txt
```

The script loads `princeton-nlp/SWE-bench` **train** instances, checks out each issue's `base_commit`, runs GraphMem retrieval, creates candidate features and patch-derived labels, and fits LambdaMART. Repository cloning, parsing, graph construction and history extraction can make this slow. Increase `--max-instances` gradually after validating the run. The default is 200 sampled training instances, not the entire dataset.

The script uses an issue-level 80/20 split of the sampled *training* instances for model fitting and early stopping. It never trains on SWE-bench Lite or SWE-bench Verified test examples. Keep the Lite/Verified evaluation set untouched for final reported results.

Artifacts written:

- `models/graphmem-lambdamart.txt`: LightGBM model.
- `models/graphmem-lambdamart.txt.json`: feature schema and training metadata.

Labels are graded: `2` when a candidate callable/span overlaps gold changed lines, `1` for a file-level candidate matching a changed file, and `0` otherwise. The labels are weak supervision derived from the gold patch; they are not a claim that every unchanged candidate is truly irrelevant.

## 3. Use the trained model

```bash
graphmem-localize localize /path/to/repository "Describe the bug here" \
  --ranker models/graphmem-lambdamart.txt --top-k 10
```

The model reorders scopes generated by the normal GraphMem retrieval pipeline. It does not access the gold patch at inference time. Without `--ranker`, the existing hand-weighted ranking is used.

## 4. Evaluation protocol

Compare at least these systems on the same held-out SWE-bench Lite subset:

1. Existing manual-weight ranker (no `--ranker`).
2. Learned LambdaMART ranker (`--ranker ...`).
3. Existing ablations, if you are reporting contribution of each evidence source.

Report Acc@1, Acc@3, Acc@5, Recall@5, MRR, candidate coverage, and runtime. Tune on a development set only; do not tune on the held-out test instances. Save the selected seed, subset IDs, model metadata, and run summaries for reproducibility.

## Current limitations

- The initial model re-ranks scope-level candidates. Statement ranking still uses GraphMem's existing statement score.
- The current feature vector uses lexical, graph, data-flow, history, artifact and semantic signals when present, baseline score, scope size, path depth, query-token overlap, and candidate type. Signals unavailable during retrieval default to zero.
- Training only sees candidates generated by the current retrieval pipeline. It cannot rank a gold location that candidate generation never retrieves; track candidate coverage separately.
- The default training cap is intentionally conservative. For final experiments, train with a larger sample if compute permits, then evaluate once on the untouched benchmark.


### Troubleshooting: `TypeError: Data list can only be of ndarray or Sequence`

This can occur with some LightGBM versions when the training matrix is passed as nested Python lists. The training script explicitly converts feature matrices to NumPy arrays and checks that feature dimensions and ranking group sizes match. If you are updating an existing checkout, replace `scripts/train_ranker.py` with the version in this archive.


## 5. Evaluate the model with `run_eval.py`

The evaluation runner accepts `--ranker` and records a separate `learned` result alongside all existing manual-weight ablations. Prepare your SWE-bench Lite subset if needed, then run a small smoke test:

```bash
python scripts/run_eval.py --prepare-dataset
python scripts/run_eval.py --split dev --pilot \\
  --ranker models/graphmem-lambdamart.txt \\
  --output results/learned-pilot
```

For the final held-out evaluation, use your preselected test subset and run:

```bash
python scripts/run_eval.py --split test \\
  --ranker models/graphmem-lambdamart.txt \\
  --output results/learned-test
```

The report will include `learned` separately from the manual ablations. Do not tune the model using the final test results. Ensure the trained model and test subset are fixed before reporting results.
